# Учебный проектный офис (УПО)

Простое веб-приложение для управления проектами, задачами и персоналом. Разработано для проведения ролевых игр на курсах обучения профессии «Системный аналитик».

## Назначение

Занятия на курсах проходят в форме вебинаров. Преподаватель вызывает добровольцев, назначает роли стейкхолдерам и системному аналитику. Стейкхолдеры придумывают проект, а системный аналитик набирает команду из добровольцев и моделирует полный жизненный цикл выполнения нескольких проектов в течение одного-двух занятий.

В ходе игры преподаватель «подбрасывает» вводные, требующие оперативной реакции системного аналитика (форс-мажор, изменение внешних условий, болезнь сотрудников, изменение конъюнктуры, необходимость оперативного отчёта и т.д.).

Приложение спроектировано максимально простым, чтобы любой слушатель курсов (в том числе далёкий от ИТ) мог оперативно скачать, установить и использовать его самостоятельно.

## Технологии

- **Python 3.12+**
- **FastAPI** — веб-фреймворк (серверный рендеринг Jinja2)
- **Uvicorn** — ASGI-сервер для продакшена
- **SQLAlchemy 2.0 + Alembic** — доступ к данным и миграции схемы
- **SQLite** — хранение данных (файл в `data/upo_database.db`)
- **uv** — управление зависимостями и виртуальным окружением
- **ruff + mypy + pre-commit** — линтеры и проверки перед коммитом
- **Docker** (опционально) — контейнеризация для развёртывания

## Установка и запуск (локально)

```bash
# Установка зависимостей
uv sync

# Запуск приложения (dev-сервер)
.venv/bin/python main.py

# Приложение доступно по адресу:
# http://127.0.0.1:5000
```

Альтернативно с использованием `uv run`:

```bash
uv run python main.py
```

При первом запуске автоматически создаётся база данных, применяются миграции Alembic
и заполняются справочники.

## Запуск в продакшене

Через uvicorn (инициализация БД происходит при импорте приложения):

```bash
UPO_SECRET_KEY="<случайный ключ>" .venv/bin/uvicorn app.main:app --workers 1 --host 0.0.0.0 --port 5000
```

Или через Docker:

```bash
docker compose up -d --build
# доступ: http://<IP-адрес>:5000
```

> Примечание: SQLite — файловая БД, поэтому рекомендуется один воркер uvicorn (`--workers 1`). Данные и бэкапы хранятся в `data/` (в Docker — смонтированы в volume `./data:/app/data`).

## Возможности

- **Главная страница** — сводные показатели (проекты, активные и просроченные задачи, сотрудники, события).
- **Справочники** — приоритеты, типы стейкхолдеров, типы требований, типы должностей, статусы сотрудников, типы этапов, статусы этапов, статусы задач, типы задач.
- **Стейкхолдеры** — ведение карточек, типы, влияние/заинтересованность, приоритет.
- **Проекты** — создание, редактирование, главный стейкхолдер, команда, этапы, связи со стейкхолдерами и исполнителями.
- **Требования** — бизнес-, пользовательские, функциональные и нефункциональные требования с критериями приёмки.
- **Сотрудники** — должности, статусы (работает, болеет, в командировке и т.д.), доступность.
- **Задачи и подзадачи** — декомпозиция в дереве (этапы → задачи → вложенные подзадачи), типы задач, приоритеты, статусы, сроки (просроченные — красным), комментарии.
- **Назначения** — распределение задач между сотрудниками с долями загрузки; у подзадачи — только один исполнитель; суммарная загрузка сотрудника не более 100%.
- **Этапы проекта** — жизненный цикл: инициация → анализ → проектирование → разработка → тестирование → внедрение → закрытие.
- **События** — фиксация вводных преподавателя (форс-мажор, изменения) и принятых решений.
- **Интервью со стейкхолдерами** — вопросы и ответы (редактируются прямо в карточке интервью), диктофон (запись с микрофона) и локальная транскрибация с посегментными таймкодами и метками спикеров, экспорт в Markdown.
- **Шаблоны интервью** — новое интервью создаётся с нуля или по выбранному шаблону; шаблон можно создать вручную или из вопросов прошедшего интервью. Есть предзаполненный шаблон «Вопросы Заказчику».
- **Отчёты** — сводки и аналитика по проектам, стейкхолдерам, сотрудникам, требованиям, этапам, задачам, подзадачам, назначениям и событиям; сущности в отчётах — ссылки на карточки.
- **Управление базами данных** — объединение нескольких игр в отдельные БД, переключение между ними, удаление и **копирование файла БД** (копия создаётся без изменений; удаление данных — только вручную). Резервные копии складываются в `data/backups/` и не удаляются автоматически.
- **Аутентификация и роли** — вход по логину/паролю (кнопка «Вход/Выход» в правом краю меню), регистрация; роли «администратор» и «пользователь».
- **Аудит** — неизменяемый журнал действий с фильтрами/сортировкой по проекту, должности и пользователю.
- **Чат** — общая лента сообщений: чтение доступно всем, отправка — после входа.
- **«Мои задачи»** (пользователь) и **«Задачи»** (администратор: вкладки «Не назначенные», «Не принятые к исполнению», «Просроченные»).
- **Настройки** — разрешение пользователям назначать исполнителей подзадач.
- **Автор назначения** — для каждой задачи/подзадачи сохраняется, кто назначил исполнителя; отображается на карточках.

## Аутентификация и роли

Чтение всех разделов доступно анонимно. Для любых изменений нужно войти.

- **Администратор** — полный доступ на запись: справочники, проекты, сотрудники, задачи, назначения, настройки; разделы «Аудит», «Настройки», «Задачи».
- **Пользователь** — полный доступ на чтение, а также: создание/ведение подзадач в своих задачах (рекурсивно), смена статуса своих задач/подзадач, комментарии, чат, назначение исполнителя подзадачи (с учётом настройки).
- При регистрации автоматически создаётся «Сотрудник» с должностью «Пользователь»; администратор может изменить должность и роль пользователя в разделе «Сотрудники» (роль отображается всем, менять свою роль нельзя).

**Пользователь по умолчанию:** логин `admin`, пароль `12345` (роль «администратор»).

> Пароли хранятся в виде хешей (PBKDF2-HMAC-SHA256). Старые записи с паролем в открытом
> виде автоматически перехешируются при первом успешном входе.

## Архитектура

Строгое разделение слоёв (`app/`):

```
app/
├── main.py              # create_app(): FastAPI, middleware, static, роутеры
├── config.py            # пути, окружение, секрет
├── dependencies.py      # get_db, current_user, require_admin/user/analyst
├── security.py          # хеширование паролей, safe_next
├── audit.py             # аудит действий (глобальная зависимость)
├── urls.py              # Flask-совместимый url_for (относительный + query)
├── db/                  # модели SQLAlchemy, engine, seed, Alembic-миграции
├── repositories/        # только SQL/ORM
├── services/            # бизнес-логика
├── api/                 # контроллеры (HTTP): auth, projects, tasks, interviews, …
└── presentation/        # Jinja2-шаблоны, макросы и построение HTML
```

Направление зависимостей: `api → services → repositories`; HTML формируется только в
`presentation`. Слои проверяются тестом `tests/unit/test_layering.py`.

## Тестирование и проверки

Все проверки работают на **отдельной** тестовой БД и никогда не трогают рабочую
`data/upo_database.db`:

```bash
uv run pytest            # pytest-набор (маршруты, бизнес-правила, слои, схема)
uv run python dev.py     # smoke-сценарий основных операций

# Линтеры и типы
uv run ruff check .
uv run ruff format --check .
uv run mypy app

# Всё сразу перед коммитом
uv run pre-commit install
uv run pre-commit run --all-files
```

`tests/endpoints_baseline.txt` фиксирует набор маршрутов (`path`, `endpoint`) — тест ловит
любое изменение URL/имён endpoint, от которых зависит `url_for`.

## Транскрибация интервью (опционально)

В карточке интервью: нажмите **«● Записать»**, остановите **«■ Стоп»**, затем нажмите **«Распознать (Whisper)»** — появится транскрипт с посегментными таймкодами (спикера можно проставить вручную).

Локальное распознавание работает на CPU при установленной библиотеке:

```bash
uv sync --extra transcription     # faster-whisper (рекомендуется, int8 на CPU)
# или: pip install pywhispercpp   # движок whisper.cpp (как в Buzz)
```

Требуется `ffmpeg` для декодирования аудио. Без установленной библиотеки приложение работает как обычно, а кнопка «Распознать» сообщит, что движок не установлен.

> Для записи с микрофона браузер требует **HTTPS** (или `localhost`). Запись страницы ловит микрофон; при интервью по видеосвязи голос собеседника — через захват аудио вкладки/системный loopback или загрузку записи платформы. Диаризация («кто говорил») — опционально; метки спикеров можно проставить вручную в таблице транскрипта.

## Конфигурация (переменные окружения)

- `HOST` — адрес для прослушивания (по умолчанию `0.0.0.0`), `PORT` — порт (по умолчанию `5000`).
- `UPO_DATABASE` — имя рабочей базы данных (по умолчанию `upo_database.db`).
- `UPO_SECRET_KEY` — ключ подписи сессии. Если не задан, генерируется случайный на время процесса (сессии не сохраняются между перезапусками и между воркерами — задайте ключ для продакшена).
- `UPO_DEBUG` — включить debug-режим (`1`), по умолчанию выключен.
- `UPO_STT_MODEL` — модель распознавания (`base`/`small`, по умолчанию `small`), `UPO_STT_LANGUAGE` (`ru`).
- `UPO_AUDIO_DIR` — каталог аудиозаписей (по умолчанию `data/audio`).
