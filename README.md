# Учебный проектный офис (УПО)

Простое веб-приложение для управления проектами, задачами и персоналом. Разработано для проведения ролевых игр на курсах обучения профессии «Системный аналитик».

## Назначение

Занятия на курсах проходят в форме вебинаров. Преподаватель вызывает добровольцев, назначает роли стейкхолдерам и системному аналитику. Стейкхолдеры придумывают проект, а системный аналитик набирает команду из добровольцев и моделирует полный жизненный цикл выполнения нескольких проектов в течение одного-двух занятий.

В ходе игры преподаватель «подбрасывает» вводные, требующие оперативной реакции системного аналитика (форс-мажор, изменение внешних условий, болезнь сотрудников, изменение конъюнктуры, необходимость оперативного отчёта и т.д.).

Приложение спроектировано максимально простым, чтобы любой слушатель курсов (в том числе далёкий от ИТ) мог оперативно скачать, установить и использовать его самостоятельно.

## Технологии

- **Python 3.12+**
- **Flask 3.1.3** — веб-фреймворк
- **SQLite** — хранение данных (файл в `data/upo_database.db`)
- **uv** — управление зависимостями и виртуальным окружением

## Установка и запуск

```bash
# Установка зависимостей
uv sync

# Запуск приложения
.venv/bin/python main.py

# Приложение доступно по адресу:
# http://127.0.0.1:5000
```

Альтернативно с использованием `uv run`:

```bash
uv run python main.py
```

При первом запуске автоматически создаётся база данных и заполняются справочники.

## Возможности

- **Главная страница** — сводные показатели (проекты, активные и просроченные задачи, сотрудники, события).
- **Справочники** — приоритеты, типы стейкхолдеров, типы требований, типы должностей, статусы сотрудников, типы этапов, статусы этапов, статусы задач.
- **Стейкхолдеры** — ведение карточек, типы, влияние/заинтересованность, приоритет.
- **Проекты** — создание, редактирование, главный стейкхолдер, команда, этапы, связи со стейкхолдерами и исполнителями.
- **Требования** — бизнес-, пользовательские, функциональные и нефункциональные требования с критериями приёмки.
- **Сотрудники** — должности, статусы (работает, болеет, в командировке и т.д.), доступность.
- **Задачи и подзадачи** — декомпозиция, приоритеты, статусы, сроки.
- **Назначения** — распределение задач между сотрудниками с долями загрузки.
- **Этапы проекта** — жизненный цикл: инициация → анализ → проектирование → разработка → тестирование → внедрение → закрытие.
- **События** — фиксация вводных преподавателя (форс-мажор, изменения) и принятых решений.
- **Интервью со стейкхолдерами** — вопросы и ответы, экспорт в Markdown.
- **Отчёты** — сводки и аналитика по проектам, стейкхолдерам, сотрудникам, требованиям, этапам, задачам, подзадачам, назначениям и событиям.
- **Управление базами данных** — объединение нескольких игр в отдельные БД, переключение между ними, удаление. Резервные копии создаются в `data/backups/`.

## Структура проекта

```
my_jira/
├── main.py            # основной код приложения (Flask + БД + шаблоны)
├── dev.py             # smoke-тесты на отдельной тестовой БД
├── pyproject.toml     # конфигурация проекта и зависимостей
├── uv.lock            # lock-файл зависимостей
├── .python-version    # версия Python (3.12)
├── data/
│   ├── upo_database.db    # рабочая база данных
│   └── backups/           # резервные копии БД
└── references/
    └── task.md            # описание назначения и требований
```

## Тестирование

Скрипт `dev.py` выполняет smoke-проверки на отдельной тестовой БД и никогда не трогает рабочую базу `data/upo_database.db`.

```bash
.venv/bin/python dev.py
```

## Конфигурация

- Порт и хост по умолчанию: `127.0.0.1:5000` (можно изменить в блоке запуска в `main.py`).
- Имя рабочей базы данных задаётся переменной окружения `UPO_DATABASE` (по умолчанию `upo_database.db`).
