# 7. Функциональные требования

Формат: `FR-N Описание. Приоритет (Мо/До/Хо). Критерий приёмки.`

## 7.1 Справочники
- **FR-01** Ведение справочников и их CRUD. *Мо.* Критерий: можно добавить/изменить/удалить приоритеты, типы стейкхолдеров/требований/должностей/этапов, статусы сотрудников/этапов/задач, типы задач.
- **FR-02** Типы задач по умолчанию: новый функционал, исправление ошибки, улучшение, документирование, тестирование, код-ревью. *Мо.* Критерий: при первичной инициализации и на существующих БД список присутствует (идемпотентно).

## 7.2 Проект
- **FR-10** Создание/редактирование проекта с главным стейкхолдером. *Мо.*
- **FR-11** Карточка проекта с вкладками «Требования», «Этапы», «Стейкхолдеры», «Исполнители». *Мо.* Критерий: вкладки переключаются, сохраняется активная вкладка после действий (`?tab=`).

## 7.3 Стейкхолдеры
- **FR-20** Стейкхолдер с типом (влияние/интерес), должностью, приоритетом; приоритет по умолчанию из типа. *Мо.*
- **FR-21** Связь «проект ↔ стейкхолдер» и выбор из имеющихся, удаление связи. *Мо.*
- **FR-22** Автосоздание стейкхолдера-«разработчика» из сотрудника с флагом «является стейкхолдером»; синхронизация в обе стороны без зацикливания. *Мо.*
- **FR-23** Интервью (дата-время, вопросы-ответы, экспорт Markdown). *До.*
- **FR-24** Аудиозапись интервью: запись с микрофона (диктофон), загрузка аудиофайла, прослушивание и скачивание. *До.*
- **FR-25** Транскрипт интервью с **посегментными таймкодами**: локальное распознавание (Whisper, опционально) либо импорт SRT/VTT/TXT (в т.ч. из Buzz); правка текста, метка спикера, удаление сегмента, очистка. *До.*
- **FR-26** Диаризация — опционально (автоматическая точка расширения) либо ручные метки спикеров. *Хо.*

## 7.4 Требования
- **FR-30** Требование с типом, приоритетом, критерием приёмки, привязкой к проекту и стейкхолдеру. *Мо.*
- **FR-31** Определение «реализовано» (есть задачи по требованию). *До.*

## 7.5 Этапы, задачи, подзадачи
- **FR-40** Этапы с типом и статусом; жизненный цикл. *Мо.*
- **FR-41** Задача обязана иметь требование, тип задачи, этап. *Мо.* Критерий: без любого из них задача не создаётся/не сохраняется.
- **FR-42** Подзадачи с вложенностью; этап подзадачи наследуется от родителя. *До.*
- **FR-43** Отображение срока; просроченные — красным. *До.*
- **FR-44** Дерево «этап → задачи → подзадачи» без описаний, с переходами в карточки. *До.*

## 7.6 Исполнители и загрузка
- **FR-50** Назначение задач/подзадач на исполнителей из проекта; должность и загрузка видны при назначении. *Мо.*
- **FR-51** У подзадачи только один исполнитель (замена при повторном назначении). *Мо.*
- **FR-52** Суммарная загрузка сотрудника ≤ 100%; доля по умолчанию делится поровну; сумма может быть < 100%. *Мо.*
- **FR-53** Занятость в подзадаче исключает занятость в родительской задаче/подзадаче (не учитывается и не отображается). *До.*

## 7.7 Комментарии
- **FR-60** Комментарии к задачам/подзадачам; последний сверху; автор — из исполнителей проекта. *До.*
- **FR-61** Комментарии живут в карточках (в дереве не отображаются). *До.*

## 7.8 Отчёты, события, БД
- **FR-70** Отчёты по сущностям; сущности — ссылки на карточки. *До.*
- **FR-71** События (вводные, решения). *До.*
- **FR-72** Управление базами данных, переключение активной БД, резервные копии. *До.*
- **FR-73** Экспорт интервью в Markdown. *До.*
