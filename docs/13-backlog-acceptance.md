## 13.2 Критерии приёмки (ключевые)
- **Задача:** не создаётся без требования/этапа/типа.
- **Назначение:** только исполнители проекта; у подзадачи — один; суммарная загрузка сотрудника не превышает 100%; при переназначении исполнителя подзадачи происходит замена.
- **Загрузка:** занятость в подзадаче исключает занятость в родительской задаче/подзадаче (не учитывается и не отображается).
- **Интервью:** экспорт — файл `interview_<id>.md` с вопросами-ответами.
- **БД:** создание новой БД с именем, переключение, удаление (основную `upo_database.db` удалить нельзя); активная БД отображается в шапке; бэкапы в `data/backups/`.
- **Справочники:** типы задач присутствуют по умолчанию и на существующих БД (идемпотентно).
- **Синхронизация «сотрудник ↔ стейкхолдер-разработчик»:** установка флага создаёт стейкхолдера; снятие — удаляет; без зацикливания.

## 13.3 Метрики успеха
- Полный цикл учебного проекта ведётся за одно занятие.
- Минимум действий ведущего: создал проект → назначил → сформировал события/отчёты.
- Отчёты и карточки дают материал для разбора.
