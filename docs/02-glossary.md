# 2. Глоссарий

| Термин | Определение |
|--------|-------------|
| **УПО** | Учебный проектный офис — приложение / предметная область. |
| **Проект** | Единица моделируемой деятельности: название, сроки, стоимость, главный стейкхолдер, приоритет. |
| **Стейкхолдер** | Заинтересованное лицо проекта; имеет тип, влияние/интерес, должность, приоритет. |
| **Тип стейкхолдера** | Справочник, задающий влияние и интерес (матрица власти/интереса). |
| **Главный стейкхолдер** | Основной заинтересованный (владелец) проекта. |
| **Требование** | Потребность, сформулированная стейкхолдером и привязанная к проекту; имеет тип, приоритет и критерий приёмки. |
| **Тип требования** | Справочник: бизнес-, пользовательское, функциональное, нефункциональное и др. |
| **Этап проекта** | Фаза жизненного цикла (инициация → анализ → проектирование → разработка → тестирование → внедрение → закрытие). |
| **Статус этапа** | Не начат / в работе / на паузе / завершён / отменён. |
| **Сотрудник / исполнитель** | Член команды: должность, статус, доступность, флаг «является стейкхолдером». |
| **Исполнители проекта** | Сотрудники, назначенные на проект (связь «проект ↔ сотрудник»). |
| **Задача** | Работа в рамках этапа; обязана иметь требование, тип задачи, этап, приоритет, статус, срок. |
| **Тип задачи** | Справочник: новый функционал, исправление ошибки, улучшение, документирование, тестирование, код-ревью. |
| **Подзадача** | Декомпозиция задачи; может вкладываться в другую подзадачу; имеет одного исполнителя. |
| **Назначение** | Связь «сотрудник ↔ задача/подзадача» с долей загрузки (0–100%). |
| **Загрузка сотрудника** | Суммарная доля по эффективным назначениям; не более 100%. |
| **Интервью** | Встреча со стейкхолдером (дата-время) с вопросами и ответами. |
| **Комментарий** | Заметка к задаче/подзадаче (автор, текст, дата). |
| **Событие** | Зафиксированная вводная преподавателя (форс-мажор, изменение условий) и принятое решение. |
| **Справочник** | Словарная таблица (типы, статусы, приоритеты, должности). |
| **БД игры** | Отдельная база данных на одну игру; переключение между ними из интерфейса. |
| **Карточка** | Детальная страница сущности (проект, задача, стейкхолдер и т.д.). |
| **Дерево этапов** | Иерархическое представление «этап → задача → вложенные подзадачи» на странице проекта. |
