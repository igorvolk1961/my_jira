# 14. Риски и допущения

## 14.1 Риски разработки/использования
| ID | Риск | Вероятность | Влияние | Митигация |
|----|------|-------------|---------|-----------|
| R-01 | Потеря данных (удаление файла БД) | Средняя | Высокое | БД в `data/`, авто-бэкапы в `data/backups/`, восстановление копией |
| R-02 | Конфликты записи при нескольких процессах SQLite | Средняя | Среднее | Один воркер gunicorn (`-w 1`); при росте — серверная СУБД |
| R-03 | Подделка сессии при дефолтном ключе | Средняя | Среднее | `UPO_SECRET_KEY` из окружения в прод |
| R-04 | Несогласованность артефактов с кодом | Средняя | Среднее | Соответствие документов реализованной модели; обновление при изменениях |
| R-05 | «Курица-яйцо» при назначении в подзадачу (загрузка) | Низкая | Среднее | Логика: подзадача покрывает предков (проекция загрузки) |
| R-06 | Дублирование стейкхолдеров/исполнителей | Низкая | Низкое | Выбор из имеющихся + UNIQUE-ограничения |
| R-07 | Ошибки навигации (вкладки, кнопки) | Низкая | Низкое | Автотесты `dev.py` на отдельной БД |
| R-08 | Масштабирование (много игр/данных) | Низкая | Среднее | Отдельные БД на игру |

## 14.2 Допущения
- В учебном формате не требуется авторизация и разграничение прав — все действуют через общий интерфейс.
- Объёмы данных невелики (несколько проектов/команд).
- SQLite достаточно для одного сервера и одного-двух пользователей одновременно.
- Артефакты иллюстративны и могут быть расширены под конкретное занятие.

## 14.3 Решение по хранению
- Файловая БД `data/upo_database.db`; имя задаётся `UPO_DATABASE`.
- Резервные копии — `data/backups/` (автоматически при старте, хранится до 20 копий).
- Для Docker — volume `./data:/app/data`.
