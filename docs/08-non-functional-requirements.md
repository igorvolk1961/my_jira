# 8. Нефункциональные требования

| Код | Категория | Требование | Критерий |
|-----|-----------|------------|----------|
| NFR-01 | Простота освоения | Минимум обучения; интуитивные формы. | Слушатель без ИТ-опыта выполняет основной сценарий за занятие. |
| NFR-02 | Производительность | Быстрый отклик для малого объёма данных (учебный формат). | Отклик страниц < 1 с при десятках проектов/задач. |
| NFR-03 | Доступность | Один ведущий может вести занятие. | Достаточно одного процесса (1 воркер gunicorn). |
| NFR-04 | Надёжность данных | Данные сохраняются и не теряются при перезапуске. | Файловая БД в `data/`, авто-резервные копии в `data/backups/`. |
| NFR-05 | Безопасность сессии | Подпись сессии секретным ключом; настройка через `UPO_SECRET_KEY`. | Случайный ключ задаётся в прод; без него — дефолтный. |
| NFR-06 | Переносимость | Работа локально и на VPS. | Python 3.12+, запуск `python main.py`, gunicorn или Docker. |
| NFR-07 | Расширяемость | Добавление/изменение справочников без правки кода. | CRUD справочников в интерфейсе. |
| NFR-08 | Целостность данных | Ограничения: задача без требования/этапа/типа — не создаётся; загрузка ≤ 100%; один исполнитель у подзадачи; каскадное удаление. | Проверки в коде + ограничения БД (индексы, FK). |
| NFR-09 | Ведение нескольких игр | Разделение данных по базам. | Отдельная БД на игру, переключение, бэкапы. |
| NFR-10 | Удобство навигации | Переходы между сущностями (карточки, ссылки). | Все ключевые сущности кликабельны. |
